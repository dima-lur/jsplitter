performance

js/performance.js:154

High-resolution timing API implementing the JSplitter subset of the Web High Resolution Time, User Timing, and Performance Timeline APIs.
JSplitter currently records only user-created "mark" and "measure" entries; browser-specific navigation, resource, paint, and similar performance entry types are not available.
For the corresponding Web standards, see High Resolution Time, User Timing, and Performance Timeline.

mark(name, markOptions)

Creates a named PerformanceEntry with entryType "mark" and adds it to the performance timeline.
Multiple marks may use the same name. All marks remain in the timeline until cleared; when a mark name is later used by performance.measure, the most recently created matching mark is used.

Parameters

NameTypeDescription
namestring

markOptionsoptionalPerformanceMarkOptions

Optional mark timestamp and metadata.

Returns

Throws

Example

  detail: { description: "Begin of some important work", id: 777 }

measure

js/performance.js:199
measure(measureName, startOrMeasureOptions, endMark, legacyMeasureOptions)

Creates a named PerformanceEntry with entryType "measure" and adds it to the performance timeline.

Standard forms supported by JSplitter:
performance.measure(name) - measures from timestamp 0 to performance.now.
performance.measure(name, startMark) - measures from the most recent named start mark to now.
performance.measure(name, startMark, endMark) - measures between the most recent matching named marks.
performance.measure(name, options) - derives start/end times from PerformanceMeasureOptions.
performance.measure(name, {}, endMark) - measures from timestamp 0 to the named end mark.

In options, start and end may be either mark names or finite non-negative timestamps. duration may be supplied with exactly one of start or end. If an explicitly named mark does not exist, an error is thrown.
Multiple measures may use the same name. Named mark lookup always uses the most recently created matching mark.

Compatibility note: for historical JSplitter compatibility, a fourth legacyMeasureOptions argument is also accepted. This form preserves the previous JSplitter precedence rules: existing explicit startMark/endMark values take precedence, while numeric start, end, or duration options fill missing values. New code should prefer the standard forms above.
For backward compatibility, an empty positional mark name ("") is treated as omitted rather than as a mark named with an empty string.

Parameters

NameTypeDescription
measureNamestring

Measure name.

startOrMeasureOptionsoptional(string|PerformanceMeasureOptions)

Start mark name or standard measure options.

endMarkoptionalstring

End mark name.

legacyMeasureOptionsoptionalObject

JSplitter legacy four-argument options object. Supports numeric start, end, duration, and arbitrary detail.

Returns

PerformanceEntry —

The created measure entry.

Throws

Error —

If a named mark cannot be resolved, a numeric timestamp/duration is invalid, or the standard options contain an invalid combination.

Example

performance.mark("work-start");
doSomething();
performance.mark("work-end");

const byMarks = performance.measure("work", "work-start", "work-end");
const byTimestamp = performance.measure("custom-range", { start: 10, duration: 25 });

console.log(byMarks.duration);
console.log(byTimestamp.duration);

now

js/performance.js:163
now()

Returns a monotonically increasing high-resolution timestamp in milliseconds relative to performance.timeOrigin. The value may contain a fractional part; actual resolution depends on the underlying system clock.
Unlike Date.now(), this timestamp is intended for measuring elapsed time and is not affected by wall-clock adjustments.

Returns

number

Example

const t0 = performance.now();
doSomething();
const t1 = performance.now();
console.log(`Call to doSomething took ${t1 - t0} milliseconds.`);
